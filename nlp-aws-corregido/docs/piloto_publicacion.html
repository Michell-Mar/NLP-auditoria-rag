Runbook de publicación · piloto

Piloto en AWS

Cómo llevar webapp-pdf/ de tu laptop a una instancia que unos cuantos testers invitados puedan usar sin que tú tengas la terminal abierta.

Alcance: testers invitados Cómputo: EC2 con rol IAM Auth: ninguna (el link es el secreto)
▚

Arquitectura del piloto

No cambia el pipeline: sigue siendo webapp-pdf/server.py subiendo a S3 e invocando el mismo Lambda. Lo único nuevo es dónde corre el servidor — de tu laptop con tu perfil de SSO, a una instancia EC2 con un rol de IAM propio, para que puedas cerrar la laptop sin tumbar el piloto.

Testers invitados tienen el link; sin login
HTTP, puerto 8000
EC2 t3.micro · webapp-pdf/server.py rol de IAM, no tu perfil personal
S3 · entradas PutObject en inputs/*
Lambda · Worker InvokeFunction
S3 · resultados GetObject en results/*
el Lambda ya trae el endurecimiento contra prompt injection
OpenAI API gpt-4o + gpt-4o-mini
Decisión ya tomada

Sin autenticación propia — el link es el secreto, para un grupo pequeño de testers invitados. El límite de concurrencia (3 auditorías simultáneas) que ya está en el código es, con esta elección, tu única barrera real contra un mal uso accidental o deliberado. Ver Lo que aceptaste al no poner login al final.

00

Redesplegar el Lambda con el endurecimiento

Los cambios de max_tokens y aislamiento del contexto viven en app/audito_rag_pdf.py, que se hornea en la imagen Docker del Lambda. Si no corres esto, tus testers auditarán con la versión sin ese endurecimiento.

terminal, en tu máquina
cd nlp-aws-corregido
export AWS_PROFILE=nlp-dev
export AWS_REGION=us-east-1
aws sso login --profile nlp-dev
cdk deploy -c openaiSecretArn="$NLP_SECRET_ARN" --outputs-file cdk-outputs.json

Confirma que cdk-outputs.json se actualizó (o al menos no cambió de forma inesperada) antes de seguir.

01

Rol de IAM para la instancia

La instancia EC2 necesita permiso para invocar ese Lambda y leer/escribir esos dos buckets — nada más. Nunca copies tu perfil nlp-dev (SSO, de un humano) a la instancia.

politica-piloto.json
{
  "Version": "2012-10-17",
  "Statement": [
    { "Effect": "Allow", "Action": "lambda:InvokeFunction",
      "Resource": "arn:aws:lambda:us-east-1:TU_CUENTA:function:NOMBRE_DEL_LAMBDA" },
    { "Effect": "Allow", "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::TU_INPUT_BUCKET/inputs/*" },
    { "Effect": "Allow", "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::TU_RESULT_BUCKET/results/*" }
  ]
}

NOMBRE_DEL_LAMBDA, TU_INPUT_BUCKET y TU_RESULT_BUCKET están en tu cdk-outputs.json (FunctionName, InputBucket, ResultBucket).

terminal
aws iam create-policy --policy-name auditor-piloto-ec2 --policy-document file://politica-piloto.json
aws iam create-role --role-name auditor-piloto-ec2-role \
  --assume-role-policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow",
  "Principal":{"Service":"ec2.amazonaws.com"},"Action":"sts:AssumeRole"}]}'
aws iam attach-role-policy --role-name auditor-piloto-ec2-role \
  --policy-arn arn:aws:iam::TU_CUENTA:policy/auditor-piloto-ec2
# Permite entrar por SSM Session Manager en vez de abrir el puerto 22
aws iam attach-role-policy --role-name auditor-piloto-ec2-role \
  --policy-arn arn:aws:iam::aws:policy/AmazonSSMManagedInstanceCore
aws iam create-instance-profile --instance-profile-name auditor-piloto-ec2-profile
aws iam add-role-to-instance-profile --instance-profile-name auditor-piloto-ec2-profile \
  --role-name auditor-piloto-ec2-role
02

Lanzar la instancia EC2

La instancia solo corre un proxy HTTP delgado — el trabajo pesado (las 9 llamadas a gpt-4o) pasa en el Lambda. t3.micro sobra.

terminal
# Grupo de seguridad: puerto 8000 abierto, SIN el 22 (usamos SSM)
aws ec2 create-security-group --group-name auditor-piloto-sg \
  --description "Piloto del auditor - solo 8000"
aws ec2 authorize-security-group-ingress --group-name auditor-piloto-sg \
  --protocol tcp --port 8000 --cidr 0.0.0.0/0

aws ec2 run-instances \
  --image-id ami-XXXXXXXX \
  --instance-type t3.micro \
  --iam-instance-profile Name=auditor-piloto-ec2-profile \
  --security-groups auditor-piloto-sg \
  --count 1 \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=auditor-piloto}]'

ami-XXXXXXXX: usa la AMI más reciente de Amazon Linux 2023 para us-east-1 (aws ec2 describe-images --owners amazon --filters "Name=name,Values=al2023-ami-*-x86_64" --query "sort_by(Images,&CreationDate)[-1].ImageId" --output text).

Recorte disponible

0.0.0.0/0 en el puerto 8000 significa que cualquiera con la IP pública de la instancia puede pegarle, no solo quien tenga el link "secreto" de la app. Si conoces de antemano las IPs de tus testers, cambia el CIDR por esas — sigue sin ser autenticación, pero acorta quién puede ni siquiera intentarlo.

03

Instalar el código en la instancia

Entra por SSM (no necesitas SSH ni una llave):

terminal, en tu máquina
aws ssm start-session --target i-XXXXXXXXXXXXXXXXX

Ya dentro de la instancia:

dentro de la instancia EC2
sudo dnf install -y python3.12 python3.12-pip git
sudo mkdir -p /opt/nlp-aws-corregido && sudo chown ec2-user:ec2-user /opt/nlp-aws-corregido
cd /opt/nlp-aws-corregido
git clone https://github.com/Michell-Mar/NLP-auditoria-rag.git . -b dev
# o: sube el código con `aws s3 cp` / `scp` vía SSM si el repo no es público

python3.12 -m venv .venv
source .venv/bin/activate
pip install -r nlp-aws-corregido/app/requirements.txt -r nlp-aws-corregido/webapp-pdf/requirements.txt
echo "$(pwd)/nlp-aws-corregido/cdk-outputs.json"   # confírmalo aquí también, o cópialo manualmente

cdk-outputs.json no va en el repo (está en .gitignore) — cópialo aparte a la instancia, por ejemplo con aws ssm start-session ... --document-name AWS-StartInteractiveCommand o simplemente pegando su contenido con cat > cdk-outputs.json <<'EOF'.

04

Correrlo como servicio (no en una terminal abierta)

/etc/systemd/system/auditor-piloto.service
[Unit]
Description=Auditor de Avisos - piloto web (PDF)
After=network.target

[Service]
Type=simple
User=ec2-user
WorkingDirectory=/opt/nlp-aws-corregido/nlp-aws-corregido
ExecStart=/opt/nlp-aws-corregido/.venv/bin/python webapp-pdf/server.py \
  --region us-east-1 --host 0.0.0.0 --port 8000
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
dentro de la instancia EC2
sudo systemctl daemon-reload
sudo systemctl enable --now auditor-piloto
sudo systemctl status auditor-piloto
sudo journalctl -u auditor-piloto -f   # logs en vivo

Sin --profile: al omitirlo, boto3 toma automáticamente las credenciales del rol de IAM de la instancia (IMDS) — nunca tu perfil SSO personal.

05

Pruébalo tú primero

  1. Consigue la IP pública: aws ec2 describe-instances --instance-ids i-XXXX --query "Reservations[0].Instances[0].PublicIpAddress" --output text.
  2. Abre http://LA_IP:8000 en tu navegador.
  3. Sube un aviso de privacidad real y espera a que termine (varios minutos — son 9 llamadas a gpt-4o).
  4. Confirma que ves el resumen, la nota de desactualización si aplica, y que puedes editar una regla y descargar el PDF.
  5. Sube un cuarto PDF a propósito mientras hay 3 corriendo — confirma que te regresa el aviso de "demasiadas auditorías en curso" (HTTP 429) en vez de aceptarlo silenciosamente.
06

Compartir con los testers

Mándales el link (http://LA_IP:8000) junto con algo así:

"Sube el PDF de un aviso de privacidad. Tarda unos minutos en procesar — no cierres la pestaña. Vas a ver el veredicto por cada uno de 9 criterios legales; puedes corregir el veredicto de cualquiera antes de descargar el PDF final. No subas documentos con información personal real de terceros sin autorización."

Como no hay cuentas, no hay forma de saber quién subió qué salvo por los timestamps en los logs (journalctl) y los nombres de archivo. Si necesitas atribuir auditorías a testers específicos, pídeles que antepongan su nombre al del archivo antes de subirlo.

07

Monitoreo durante el piloto

  • Logs del servicio: sudo journalctl -u auditor-piloto -f — verás cada subida y su estado final.
  • Logs del Lambda: aws logs tail NOMBRE_DEL_LOG_GROUP --since 1h --profile nlp-dev --region us-east-1 (el LogGroup está en cdk-outputs.json).
  • Costo de OpenAI: revisa el dashboard de uso de tu cuenta OpenAI a diario mientras dure el piloto — es el gasto que no tiene techo duro en el código (solo el límite de tokens por llamada).
  • Instancia viva: aws ec2 describe-instances --instance-ids i-XXXX --query "Reservations[0].Instances[0].State.Name".
08

Cerrar el piloto

terminal
aws ec2 terminate-instances --instance-ids i-XXXXXXXXXXXXXXXXX
aws iam remove-role-from-instance-profile --instance-profile-name auditor-piloto-ec2-profile --role-name auditor-piloto-ec2-role
aws iam delete-instance-profile --instance-profile-name auditor-piloto-ec2-profile
aws iam detach-role-policy --role-name auditor-piloto-ec2-role --policy-arn arn:aws:iam::TU_CUENTA:policy/auditor-piloto-ec2
aws iam detach-role-policy --role-name auditor-piloto-ec2-role --policy-arn arn:aws:iam::aws:policy/AmazonSSMManagedInstanceCore
aws iam delete-role --role-name auditor-piloto-ec2-role
aws iam delete-policy --policy-arn arn:aws:iam::TU_CUENTA:policy/auditor-piloto-ec2
aws ec2 delete-security-group --group-name auditor-piloto-sg

El Lambda y los buckets se quedan (son del stack de CDK, con RETAIN) — esto solo desmonta lo que agregaste para el piloto.

▚

Lo que aceptaste al no poner login

  • Cualquiera que reciba, reenvíe o adivine el link puede disparar auditorías facturables — el límite de concurrencia (3 a la vez) limita el daño, no lo elimina.
  • Sin HTTPS en la ruta rápida de este runbook: el PDF que suben los testers viaja sin cifrar entre su navegador y la instancia. Aceptable para avisos de privacidad públicos de prueba; no subas ahí documentos con datos personales reales de un tercero.
  • No hay atribución por usuario — todo lo que sabes de quién hizo qué sale de los logs y de lo que el propio tester te diga.
  • Nada expira: el link sigue vivo hasta que tú apagues la instancia en la Fase 08.

Si el piloto crece más allá de "unos cuantos testers invitados", vale la pena volver a esta conversación y agregar al menos la contraseña compartida (HTTP Basic Auth) que quedó descartada esta vez, y considerar HTTPS con un dominio propio y Caddy delante de la instancia.
